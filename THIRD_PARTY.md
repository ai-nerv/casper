# Third-party code

## maki

Two tools are ports from [maki](https://github.com/tontinton/maki), at commit `54a1529`.

The `code` tool is a port of maki's `index` tool. These files derive from maki's `plugins/index/`:

| casper | maki |
|---|---|
| `src/indexing/lua/indexer.lua` | `plugins/index/indexer.lua` |
| `src/indexing/lua/lang/*.lua`, `lang/nix/*.lua`, `lang/bazel/*.lua` | `plugins/index/lang/` |
| `src/indexing/lua/code.lua` | the handler in `plugins/index/init.lua` |
| `tests/code/helpers.lua`, `tests/code/indexer_core.lua`, `tests/code/lang/*.lua` | `plugins/index/tests/` |
| `tests/code/test_helpers.lua` | `plugins/lib/maki/test_helpers.lua` |
| `src/indexing/treesitter.rs` | `maki-lua/src/api/treesitter/` |
| the directory listing in `src/indexing.rs` | `plugins/lib/maki/dir_listing.lua` |

What changed in the Lua: `maki.treesitter` is the global `treesitter`, and `maki.split` and
`table.find` are local functions in `indexer.lua`. The specs still `require("maki.test_helpers")`,
which casper's test harness answers with `tests/code/test_helpers.lua`. The language extractors
also read the grammars Helix pins (below), where maki's crates differ: `c.lua` ends a directive at
its own newline, `go.lua` reads `method_spec`, `php.lua` and `zig.lua` find a name the older
grammar leaves unnamed, `clojure.lua` reads `tree-sitter-clojure`'s symbols rather than
`tree-sitter-clojure-orchard`'s, `dart.lua` reads `UserNobody14/tree-sitter-dart` beside
`nielsenko/tree-sitter-dart`, and `kotlin.lua` reads `fwcd/tree-sitter-kotlin` beside
`tree-sitter-kotlin-ng`. maki's specs and the golden skeletons are unchanged.

`execute` is a port of maki's `code_execution` tool: its interpreter runner, the allocator that
holds a script to its memory limit, the conversion between JSON and Python values, the Python
preamble and `gather` helper, the tool description, the output limits, and the tests that came
with them. The ported code lives in `src/scripting.rs` and `src/scripting/`.

## monty

The Python interpreter itself is [monty](https://github.com/pydantic/monty), tag `v0.0.23`, used
as a dependency under its own MIT license.

## Helix

The grammars `code` parses with are the ones [Helix](https://github.com/helix-editor/helix) pins:
`grammars.lock` is generated by `make grammars-lock` from Helix's `languages.toml` at release
`25.07.1`, each grammar's repository, revision and subpath as Helix lists them. That list is
Helix's, under the [Mozilla Public License 2.0](https://www.mozilla.org/en-US/MPL/2.0/); casper
copies no Helix source. Fetching and building a grammar on the user's machine, rather than
compiling them in, is how Helix's `hx --grammar fetch` and `hx --grammar build` work too.

## tree-sitter and the grammars

`casper grammar fetch` and `casper grammar build` compile each grammar on the user's machine with
the [tree-sitter](https://github.com/tree-sitter/tree-sitter) runtime, tag `v0.27.1`, MIT, and
`src/grammars/driver.c`. casper itself contains none of them, and this project distributes no
program built from them. Each grammar is under its own repository's license: MIT for most,
Apache-2.0 for `tree-sitter-elixir`, `tree-sitter-gleam` and `tree-sitter-hcl`, and CC0-1.0 for
`tree-sitter-clojure`.
